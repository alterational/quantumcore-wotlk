# QuantumCore Armory — WotLK 3.3.5a

Статическое веб-армори по базе предметов World of Warcraft 3.3.5a, собранное из дампа таблицы
`item_template` игрового мира **Wonder WoW** (структура YDBC/YTDB ниже 600).

Сайт показывает предметы так, как их видит игрок: игровой тултип, все характеристики, урон, броню,
сопротивления, гнёзда и сокет-бонусы, комплекты, требования по классу/расе/уровню, цены, прочность,
флаги и **полный список полей записи** из базы. Спецэффекты (использование, надевание, срабатывание
при попадании) выводятся не номерами заклинаний, а их названиями и описаниями из клиента 3.3.5a
с подстановкой значений эффектов, длительности, периодичности и перезарядки.

## Возможности

* **Каталог** — поиск по названию (русскому и английскому), номеру, характеристикам; фильтры по типу,
  подтипу, слоту, качеству, уровню предмета, наличию спецэффектов, гнёзд и комплекта; сортировки.
* **Карточка предмета** — игровой тултип, вкладки «Сводка», «Спецэффекты», «Комплект», «Параметры базы»,
  сравнение с уже надетым предметом, ссылки на Wowhead.
* **Кукла персонажа** — 20 слотов, надетые предметы, суммарные характеристики, средний уровень предметов,
  урон в секунду, прогресс комплектов и виртуальный персонаж (класс/раса/уровень) для проверки требований.
* **Сравнение** — до четырёх предметов в одной таблице с подсветкой лучших значений.
* **Два языка интерфейса** — русский и английский, включая названия предметов, заклинаний и комплектов.
* **Отдельный дамп «QC 13.1»** — 33 предмета другой ревизии базы того же сервера
  (Quantum Database Rev 9.8, 30.11.2015). Хранятся отдельным набором: совпадающие `entry`
  не перезаписывают предметы основной базы, оба варианта видны одновременно.
* **Раздел «Public»** — 193 предмета из сборного внешнего дампа. Открывается только по паролю:
  пока он не введён, файл `data/public.json` даже не запрашивается. Предметы живут отдельным
  набором и не заменяют ни основную базу, ни QC 13.1.
* **Раздел «WoWDM»** — 199 реальных кастомных предметов мира Denwer из отдельного дампа
  `world.item_template` (служебные болванки, у которых название совпадало с номером записи, в
  набор не попали). Открывается тем же паролем; пока пароль не введён, файл `data/wowdm.json`
  даже не запрашивается. Предметы живут отдельным набором с ключами `wowdm<entry>` и не заменяют
  ни основную базу, ни QC 13.1, ни Public. Дамп подключается переменной `WOWDM_SQL_PATH`
  (по умолчанию `sql/wowdm.sql`).
* **Раздел «Dump»** — 3 788 предметов из публично расшаренных папок и архивов с дампами
  `item_template` разных серверов. Каждая запись сверена с эталоном официальной базы (YTDB):
  на сайт попали только те, которых в эталоне нет или у которых отличаются название, уровень
  предмета или характеристики. Вещи разложены по 177 подразделам — по папке или архиву
  происхождения («как ветка в проводнике»), предметы из разных источников с одинаковым `entry`
  остаются независимыми сущностями (ключи вида `dump1-абв123-<entry>`) и ничего не перезаписывают
  ни в основной базе, ни друг у друга. Для каждого подраздела лежит SQL-дамп в текущем формате
  колонок (`sql/dump/<подраздел>.sql`, 139 колонок). Среди находок — 389 записей с уровнем
  предмета 300 и рисованые сеты, которых нет в официальной базе.

## Как пересобрать данные

```bash
python3 tools/parse_items.py            # проверка дампа: сколько предметов и заклинаний
python3 tools/build_data.py             # сборка data/db.json, data/qc131.json и data/public.json
KAEV_DIR=... RURU_DBC_DIR=... WOWDUMPS_DIR=... python3 tools/build_dump.py   # раздел Dump
```

Раздел Dump собирается отдельно из результатов сканирования внешних папок (`dumps/_inbox`):
группирует кандидатов по папке/архиву происхождения и пишет `sql/dump/*.sql`,
`data/dump/*.json` и `data/dump/index.json` тем же конвейером, что и остальные разделы
(переменная `RESUME=1` пропускает уже собранные подразделы).

Один запуск собирает все наборы: `data/db.json` из `sql/item_template.sql`, `data/qc131.json`
из `sql/qc131.sql` (`QC_SQL_PATH`), `data/public.json` из `sql/public.sql` (`PUBLIC_SQL_PATH`)
и, если файл есть, `data/wowdm.json` из `sql/wowdm.sql` (`WOWDM_SQL_PATH`).

Предметы дополнительных наборов получают в приложении ключи с префиксами `qc`, `pub` и `wowdm`,
поэтому записи с одинаковым `entry` не конфликтуют между собой. У каждой записи сборного дампа
сохраняется файл-источник (`meta.sourceFile`), он же показывается в «Параметрах базы».

`build_data.py` использует дамп `sql/item_template.sql` и справочники клиента 3.3.5a:

| переменная окружения | содержимое |
| --- | --- |
| `KAEV_DIR` | SQL-выгрузки клиентских DBC 3.3.5.12340 (`Spell.sql`, `ItemSet.sql`, `ItemDisplayInfo.sql`, `SpellDuration.sql`, `SpellItemEnchantment.sql`) |
| `RURU_DBC_DIR` | бинарные DBC русской версии клиента 3.3.5a (`Spell.dbc`, `SpellRadius.dbc`, `SpellItemEnchantment.dbc`, `SpellIcon.dbc`) |
| `WOWDUMPS_DIR` | выгрузки `itemsparse.csv` и `itemset.csv` для сверки названий предметов с Wowhead |

Результат — до четырёх файлов, которые читает сайт: `data/db.json` (основная база),
`data/qc131.json` (дамп QC 13.1), `data/public.json` и `data/wowdm.json` (запароленные разделы).
Отсутствующие файлы сайт просто пропускает: раздел без файла остаётся пустым, а остальные наборы
работают как обычно.

Дампы из интернета попадают в репозиторий через GitHub Actions: ссылки перечислены в
`tools/fetch-paste.list`, workflow `fetch-paste.yml` скачивает их и коммитит результат.
Строка вида `https://nopaste.net/XXXX sql/wowdm.sql` добавит дамп раздела WoWDM — после
коммита сборка сама сделает из него `data/wowdm.json` и раздел наполнится. Важно: строка
перезаписывает файл целиком, поэтому для дампов, которые в репозитории правятся руками
(у `sql/public.sql` вырезаны группы `pack_35` и `pack_36`), ссылка оставлена отключённой.

Дампы читаются как есть: подходят и `REPLACE INTO`, и `INSERT INTO`, список колонок может
отличаться от основного (в том числе прийти без запятых — он восстанавливается по известной
схеме `item_template`). Строки, у которых число значений не совпало со списком колонок,
пропускаются с предупреждением, а раздел без единой разобранной записи не собирается вовсе —
чтобы пустой файл не подменил данные молча. У названий и описаний убирается markdown-разметка
ссылок и восстанавливается кодировка cp1251, если выгрузка пришла в ней.

## Публикация

Сайт статический и публикуется GitHub Pages прямо из ветки
(Settings → Pages → Deploy from a branch → ветка → `/ (root)`):
<https://alterational.github.io/quantumcore-wotlk/>. Отдельная сборка не нужна — достаточно пуша.

## Пароль разделов Public и WoWDM

Оба запароленных раздела открываются одним паролем (`1337`), но независимы: у каждого свой файл
данных, свои ключи предметов и своя отметка «открыт» — блокировка одного не закрывает другой.
Пароль хранится в `assets/js/app.js` и проверяется в браузере: это скрытие раздела от случайного
просмотра, а не защита серверных данных — файлы `data/public.json` и `data/wowdm.json` лежат
на сайте открыто, как и сами SQL-дампы в репозитории.

## Что удалено из сборного дампа

Из `sql/public.sql` удалены две группы: `pack_35_PVE_T11_Apocalyptic.sql` (252 строки) и
`pack_36_Arena_S9_Destructive.sql` (209 строк). Эти записи не входят ни в один раздел сайта;
полный сборник со всеми группами остаётся по исходной ссылке в `tools/fetch-paste.list`.
