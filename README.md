# QuantumCore Armory — WotLK 3.3.5a

Статическое веб-армори по базе предметов World of Warcraft 3.3.5a, собранное из дампа таблицы
`item_template` игрового мира **Wonder WoW** (структура YDBC/YTDB ниже 600).

Сайт показывает предметы так, как их видит игрок: игровой тултип, все характеристики, урон, броню,
сопротивления, гнёзда и сокет-бонусы, комплекты, требования по классу/расе/уровню, цены, прочность,
флаги и **полный список полей записи** из базы. Спецэффекты (использование, надевание, срабатывание
при попадании) выводятся не номерами заклинаний, а их названиями и описаниями из клиента 3.3.5a
с подстановкой значений эффектов, длительности, периодичности и перезарядки.

## Возможности

* **Каталог** — поиск по названию (русскому и английскому), номеру, характеристикам; фильтры по типу,
  подтипу, слоту, качеству, уровню предмета, наличию спецэффектов, гнёзд и комплекта; сортировки.
* **Карточка предмета** — игровой тултип, вкладки «Сводка», «Спецэффекты», «Комплект», «Параметры базы»,
  сравнение с уже надетым предметом, ссылки на Wowhead.
* **Кукла персонажа** — 20 слотов, надетые предметы, суммарные характеристики, средний уровень предметов,
  урон в секунду, прогресс комплектов и виртуальный персонаж (класс/раса/уровень) для проверки требований.
* **Сравнение** — до четырёх предметов в одной таблице с подсветкой лучших значений.
* **Два языка интерфейса** — русский и английский, включая названия предметов, заклинаний и комплектов.
* **Отдельный дамп «QC 13.1»** — 33 предмета другой ревизии базы того же сервера
  (Quantum Database Rev 9.8, 30.11.2015). Хранятся отдельным набором: совпадающие `entry`
  не перезаписывают предметы основной базы, оба варианта видны одновременно.
* **Раздел «Public»** — 193 предмета из сборного внешнего дампа (16 источников). Открывается
  только по паролю: пока он не введён, файл `data/public.json` даже не запрашивается.
  Предметы живут отдельным набором и не заменяют ни основную базу, ни QC 13.1.
* **Раздел «WoWDM»** — 461 предмет из паков `pack_35_PVE_T11_Apocalyptic.sql` и
  `pack_36_Arena_S9_Destructive.sql` того же сборного дампа. Тоже под паролем и тоже отдельным
  набором: разделы не пересекаются между собой и с остальными базами. У каждого предмета
  в «Параметрах базы» указан файл-источник.

```
assets/js/app.js           логика: каталог, карточка, кукла, сравнение
data/db.json               собранные данные для сайта (основная база)
data/qc131.json            данные отдельного дампа QC 13.1
data/public.json           данные раздела Public (загружается после пароля)
data/wowdm.json            данные раздела WoWDM (загружается после пароля)
sql/item_template.sql      исходный дамп таблицы item_template
sql/qc131.sql              дамп QC 13.1 (33 предмета и русская локализация)
sql/public.sql             сборный дамп (12 групп-схем; делится на Public и WoWDM)
sql/wowdm.sql              выгрузка разделов WoWDM (собирается автоматически)

tools/parse_items.py       разбор SQL-дампа
tools/build_data.py        сборка data/db.json из дампа и справочников
```

## Как пересобрать данные

```bash
python3 tools/parse_items.py            # проверка дампа: сколько предметов и заклинаний
python3 tools/build_data.py             # сборка data/db.json, data/qc131.json и data/public.json
```

Один запуск собирает все наборы: `data/db.json` из `sql/item_template.sql`, `data/qc131.json`
из `sql/qc131.sql` (`QC_SQL_PATH`), а `sql/public.sql` (`PUBLIC_SQL_PATH`) делится на два раздела —
`data/public.json` и `data/wowdm.json` (`WOWDM_OUT_PATH`) по метке источника группы
(`-- source: ...`) и хвостовым комментариям строк. Заодно собирается `sql/wowdm.sql`
(`WOWDM_SQL_PATH`) — выгрузка только этих групп.

Предметы дополнительных наборов получают в приложении ключи с префиксами `qc`, `pub` и `wowdm`,
поэтому записи с одинаковым `entry` не конфликтуют между собой.

`build_data.py` использует дамп `sql/item_template.sql` и справочники клиента 3.3.5a:

| переменная окружения | содержимое |
| --- | --- |
| `KAEV_DIR` | SQL-выгрузки клиентских DBC 3.3.5.12340 (`Spell.sql`, `ItemSet.sql`, `ItemDisplayInfo.sql`, `SpellDuration.sql`, `SpellItemEnchantment.sql`) |
| `RURU_DBC_DIR` | бинарные DBC русской версии клиента 3.3.5a (`Spell.dbc`, `SpellRadius.dbc`, `SpellItemEnchantment.dbc`, `SpellIcon.dbc`) |
| `WOWDUMPS_DIR` | выгрузки `itemsparse.csv` и `itemset.csv` для сверки названий предметов с Wowhead |

Результат — четыре файла, которые читает сайт: `data/db.json` (основная база),
`data/qc131.json` (дамп QC 13.1), `data/public.json` и `data/wowdm.json` (запароленные разделы).
Отсутствующие файлы дополнительных наборов сайт просто пропускает: без них он работает
на остальных базах.

Дампы из интернета попадают в репозиторий через GitHub Actions: ссылки перечислены в
`tools/fetch-paste.list`, workflow `fetch-paste.yml` скачивает их и коммитит результат.

## Локальный запуск

```bash
python3 -m http.server 8080
# открыть http://localhost:8080/
```

## Публикация

Сайт статический и публикуется GitHub Pages прямо из ветки
(Settings → Pages → Deploy from a branch → ветка → `/ (root)`):
<https://alterational.github.io/quantumcore-wotlk/>. Отдельная сборка не нужна — достаточно пуша.

## Пароль разделов Public и WoWDM

Оба запароленных раздела открываются одним паролем (`1337`), но независимы: у каждого свой файл
данных, свои ключи предметов и своя отметка «открыт» — блокировка одного не закрывает другой.
Пароль хранится в `assets/js/app.js` и проверяется в браузере: это скрытие раздела от случайного
просмотра, а не защита серверных данных — файлы `data/public.json` и `data/wowdm.json` лежат
на сайте открыто, как и сами SQL-дампы в репозитории.

World of Warcraft, Wrath of the Lich King и связанные материалы — товарные знаки Blizzard Entertainment.
